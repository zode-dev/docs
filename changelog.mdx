<Update label="2026-11-18" description="Android, and pick an image and a size">
**Android**

- New: an Android 15 phone in a sandbox. `zode new phone --image zode/android --desktop` starts one on its home screen. Install an apk with `zode android phone install app.apk --launch`, press Home, Back and Recents, rotate it and run `adb`. Taps, typing and screenshots go through the desktop, so agents drive it like any other screen. See [Android](/concepts/android).
- x86_64 and x86 apps only, with no Google Play. Seeing the screen needs the desktop, which is on Pro and Team.

**Images**

- Choose what a sandbox runs and how big it is separately: `--image` (`zode/ubuntu-24.04`, `zode/debian-13`, `zode/fedora-45`, `zode/arch`, `zode/android` or one of your images) and `--size` (`small`, `medium`, `large`, `xlarge`). The console's new-sandbox form has the same two choices.
</Update>

<Update label="2026-11-18" description="Exits: route sandboxes through a machine you own">
**Outbound proxies and exits**

- New: [exits](/concepts/outbound). Run `zode exit run` on a machine you own, such as a home lab, and route an environment through it with `zode env egress <env> --route home=exit://home --default home`. Sites see your machine's address. The agent dials out, so you open no port and it works behind CGNAT.
- Environments can also send traffic through your own HTTP, HTTPS or SOCKS5 proxy, for every host or only chosen ones. See [Outbound proxies and exits](/concepts/outbound) and the [CLI reference](/cli/exits).
- In the console, **Environments → Outbound proxies** sets routes, and can create an exit and show its command.
- API: `GET`, `POST` `/v1/exits`, `DELETE /v1/exits/{id}`, and `GET`, `PUT`, `DELETE /v1/environments/{id}/egress`.
- MCP: `exit_list`, `exit_create`, `exit_delete`, `environment_egress`, `environment_egress_set` and `environment_egress_clear`.
- An exit that has been offline for 3 minutes sends its sandboxes direct until it reconnects; `zode exit set <name> --when-offline block` keeps them blocked instead.
- CI runners can use their own environment (`zode ci env`), so routing `default` through an exit no longer has to route CI.

**CLI**

- New: [`zode upgrade`](/cli/overview#upgrade) (or `zode update`) replaces the CLI with the latest build, checked against the published SHA-256 sums. Run the install script once more to get it.
</Update>

<Update label="2026-11-15" description="Private networking guides, ZODE_PRIVATE_IP, and CI job filters">
**Private networking**

- New guides: [How private networking works](/networking/private-networking), and setup for [Tailscale](/networking/tailscale), [Headscale](/networking/headscale) and [NetBird](/networking/netbird).
- Every `zode exec` and session of a sandbox on a private network gets `ZODE_PRIVATE_IP`, its address on your mesh.
- NetBird routers now send sandbox traffic as their own peer address, so NetBird policies for the routers' group apply. Sandboxes reached hosts on a NetBird network only from the router before.
- A host rule added to a running sandbox works at once, even for a name the sandbox already looked up.

**CI**

- The console's CI jobs list opens on the last 7 days, with filters for period, status and repository, kept in the URL. `GET /v1/ci/jobs` takes `state`, `repo`, `since` and a `before` cursor.
- CI moved to the **Run** section of the console's sidebar.
</Update>

<Update label="2026-11-14" description="Port previews, zode up and down, and the CLI covers the console">
**Security groups and private networking are on**

- Security groups are enforced on every host in `eu-central`: create them with `zode sg`, the console or the API, and attach them to sandboxes. A sandbox with groups only runs on a host that enforces them. See [Networking](/concepts/networking).
- Private networking over Tailscale, Headscale or NetBird is available: connect an environment with `zode env mesh`.
- CI warm snapshots, fan-out shards and the Enforce background run work again on every host.

**Port previews**

- `zode port <sandbox> <port>` serves a port at `https://<port>-<random>.zode.run`: private to the workspace by default, `--password` for a password shown once, or `--public`. WebSockets work, so dev servers reload live. Up to 10 per sandbox. See [Port previews](/cli/ports).
- The same in the API (`POST`, `GET /v1/sandboxes/{id}/ports`, `DELETE /v1/sandboxes/{id}/ports/{port}`) and in MCP (`port_open`).

**Move local work**

- `zode up` copies the repository you are in to a sandbox, uncommitted changes and history included, turns `.env` values into vault secrets and variables after you confirm them, and with `--session` carries on your Claude Code conversation there. `zode down` brings the work back as the branch `zode/<sandbox>` without touching your working tree. See [Move local work](/cli/up-down).
- `zode bridge <sandbox> HOST:PORT` lets a sandbox reach hosts only your machine can, for as long as it runs.

**CLI**

- New: `zode snapshot`, `zode secret`, `zode env`, `zode token`, `zode logs`, `zode stats` and `zode build` (short for `zode image build`).
- New, for workspace settings: `zode workspace`, `zode audit`, `zode billing`, `zode agent`, `zode webhook`, `zode alert`, `zode otel`, `zode sg`, `zode ai-key` and `zode team`. See [Workspace settings](/cli/workspace).
- New: `zode ci` for CI jobs, costs, the monthly cap, test selection and slow or flaky tests. See [zode ci](/cli/ci).
- New: `zode env network` and `zode env mesh` for an environment's private network.
- `zode secret set` reads the value from stdin or a prompt that does not echo, and checks the signed release of every host in your workspace's regions before it uploads. It refuses when a host does not verify, unless you pass `--unverified`.
- Every command and flag is listed on the new [CLI reference](/cli/reference).

**MCP**

- New tools: `snapshot_save`, `snapshot_list`, `snapshot_restore`, `port_open`, `sandbox_logs` and `sandbox_stats`. See [MCP server](/cli/mcp).

**Docs**

- The flight recorder, AI spend in usage and OpenTelemetry export carry data now; the notes saying hosts did not write to the recorder are gone.
- The loop breaker's `loop.mode` (`off`, `alert`, `pause`) and `POST /v1/proxying/loop/resume` are documented, as is the `ci.selection_miss` event.
- [Networking](/concepts/networking) describes security groups and private networking. Neither is switched on in `eu-central` yet.
</Update>

<Update label="2026-11-13" description="Free credit with no card; console welcome">
**Billing**

- Your Personal workspace now starts with the $10 of free credit at sign-up, no card needed. A team workspace still gets its $10 when its first card is saved, and nothing is granted twice. When credit runs out without a card, sandboxes stop as before. See [Pricing](/pricing#when-credit-runs-out).

**Console**

- A three-step welcome on your first visit: run a sandbox on your credit, connect your agent, add a card. Open it again from **Get started** on an empty Sandboxes list, from the command palette, or at `console.zode.dev/?welcome`.
- Images is in tabs, like the other pages: Your images, Official and Base images.
</Update>

<Update label="2026-11-11" description="Billing, API, CLI and SDK updates; capacity">
**Billing**

- Storage is free for the first 48 hours of every sandbox, forks included. After that it is billed on the provisioned disk as before. Compute prices are unchanged.
- Running sandboxes needs a card on file or credit left. A workspace with neither gets 402 `credit_exhausted` on create, fork and start, and its running sandboxes are stopped (hibernated, never deleted) within about 15 minutes. New workspaces start with $0 of credit; saving the first card adds the $10 signup credit. Workspaces with a card keep running and are invoiced monthly. Enterprise is exempt. See [Pricing](/pricing#when-credit-runs-out).
- A Pro trial now gets Pro's limits: 15 sandboxes running at once, 20 custom images kept and 2 building at once, and the desktop.
- Enterprise keeps flight recorder data for 90 days.
- The `balance.low`, `invoice.created`, `invoice.paid` and `invoice.payment_failed` webhooks and alerts are now sent. See [Webhooks](/concepts/webhooks-and-telemetry#event-types).

**API**

- `plan_required` is now always HTTP 402. It was 403 for the desktop on create, fork and `PATCH /v1/sandboxes/{id}/features`, and for workspace defaults in `PATCH /v1/org`.
- 429 `rate_limited` answers carry `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` next to `Retry-After`.
- The OpenAPI spec lists every error `code` the API returns, validates cleanly, and documents the four sandbox sizes and the one region, `eu-central`. Codes stay an open set: handle unknown ones by HTTP status.
- A sandbox created without a size is `small` (2 vCPU, 4 GB, 50 GB) in the API, CLI and MCP. The size named `default` is not the default.
- Exec `env` is merged into the default environment, with your entries winning; it never replaced it, and the spec now says so.
- Deleting a workspace answers `key_destroyed: false`: destroying the workspace key has not shipped yet.
- Loop breaker alerts say the breaker "flagged a possible loop" unless the host enforces it.

**CLI and MCP**

- `zode exec` and `zode ssh` run a single command argument through `bash -lc`, so `zode exec demo -- 'npm ci && npm test'` works. Several arguments still run as argv. A missing program reads `command not found: X`.
- `zode new` takes `--environment`, `--pr` and `--max-cost`. `zode fork` takes `--branch`, `--pr` and `--max-cost`.
- `zode desktop` exits 1 when the desktop is off.
- `zode image build -f` refuses a Dockerfile over 64 KB before uploading it.
- The CLI says "API key" instead of "token", and `zode verify` failures no longer show host file paths.
- The MCP `sandbox_create` tool takes `image`, `browser`, `desktop`, `git_repo`, `git_branch` and `pr_number`.

**TypeScript SDK** (`@zodedev/sdk` 0.2.0)

- `Sandbox.create({ image })` boots from a custom image.
- `sbx.featureError` says why a browser or desktop asked for at create or fork did not start.
- `sbx.restore(snap)` refuses another sandbox's snapshot with `wrong_sandbox`.
- The missing-key error points to the console's API keys page.

**Official images**

- Zode now builds [official images](/concepts/official-images) for every workspace, in every size, on every host. CI jobs (`runs-on: zode-*`) use `ci-ubuntu-24.04`. Sandboxes can ask for `zode/base` with `zode new --image zode/base` or `"image": "zode/base"`.
- A new version goes live on every host at once when all its builds are ready. The previous version is kept for 24 hours.
- `GET /v1/official-images` lists each published line with its version, sizes and installed software. It needs no API key. The Dockerfiles are in [zode-dev/runner-images](https://github.com/zode-dev/runner-images).

**Capacity**

- A second host in `eu-central` adds room for more sandboxes.
</Update>

<Update label="2026-11-10" description="SDK on npm, new desktop view">
- `@zodedev/sdk` is on npm under the Apache-2.0 licence. The current version is 0.1.1. See [TypeScript SDK](/sdk/overview).
- The desktop's live view is now a page you embed in an iframe (`POST /v1/sandboxes/{id}/desktop/session`, `desktop.viewUrl()` in the SDK). It is watch-only unless you ask for `control`, and it replaces the earlier WebRTC stream.

<Update label="2026-11-09" description="Browser, desktop, custom images, plan limits">
- Sandboxes can run Chrome, driven over CDP, and a Linux desktop. Each is a switch: `browser` and `desktop` on create and fork, or `PATCH /v1/sandboxes/{id}/features`. The desktop needs Pro, Team or Enterprise.
- CDP URLs now connect straight to the sandbox's host.
- Custom images: `zode image build` from a Dockerfile or a list of commands, then boot sandboxes from the image.
- First version of the TypeScript SDK.
- `zode verify` checks a host's signed release against the Rekor transparency log. Hosts do not have signed releases installed yet, so it reports them as not verified.
- Plans now limit sandboxes running at once: Free 2, Pro 15, Team 50. Over the limit, create, fork and start fail with `concurrency_limit`.
- Sandbox creates and forks are rate-limited per person and per workspace (`rate_limited`).
- Sign-up refuses throwaway email domains.
- Spend caps live in one place, **Billing**. The daily cap and the per-sandbox default set there apply everywhere.
- Free workspaces can start a 7-day Pro trial with no card. Promo codes can be redeemed in **Billing**.
- New agent harnesses: pi and Kimi Code. Amazon Bedrock, Vertex AI and DeepSeek work through the AI proxy.
- `GET /v1/concurrency` shows how many sandboxes count against the plan limit.
- Console: a running-sandbox counter, Cmd+K search, a status page backed by `GET /v1/status`, a Support link, a new sign-in page and a theme switcher.
- AI agents can sign in to Zode as themselves with AgentID.
- Fixed: Claude subscription sign-in hung after a refused code.
- Fixed: a subscription sign-in in progress was lost when the API restarted.
</Update>

<Update label="2026-11-08" description="Real sandboxes, CLI, MCP, workspaces">
- Sandboxes run as Cloud Hypervisor microVMs in four sizes, with `POST /v1/sandboxes/{id}/exec` and a **Shell** tab in the console.
- The `zode` CLI: `login`, `new`, `ls`, `ssh`, `exec`, `fork`, `stop`, `start` and `rm`, with real interactive shells.
- `zode mcp` runs an MCP server on stdio for Claude Code, Codex and other agents.
- Every sandbox has a full dev stack: PostgreSQL and Redis running, Docker, Node 22 with pnpm and yarn, Bun, Python, Go, Rust, SQLite, `gh`, Chrome, Claude Code and Codex.
- `zode exec` and `zode ssh` take `-e KEY=VALUE` and `--env-file`.
- A sandbox created without a name gets one such as `brave-hopper`.
- Secrets are swapped in on the way out by the host's egress proxy, so sandboxes never see their values.
- Snapshots save disk and memory together; the console can take, restore and delete them.
- Use your Claude or ChatGPT subscription for Claude Code and Codex in sandboxes.
- Workspaces with roles, team members and invites.
- Console pages for account, environments, agents, CI, webhooks and OpenTelemetry export, alerts, billing and usage.
- `GET /v1/sandboxes` filters by `status`, `region` and `created_by`, and every sandbox records who created it.
- Flight recorder routes: `GET /v1/sandboxes/{id}/timeline` and `/stats`.
- Console sign-in with email and password, email links and Google, plus privacy and terms pages.
- Fixed: `zode exec` sometimes printed a read error instead of the command's exit code.
- Fixed: an out-of-memory kill ended the whole session. The CLI now reports `killed: out of memory` and the sandbox keeps working.
</Update>
