[T3 Code](https://t3.codes) runs Claude Code, Codex, Cursor and OpenCode on one machine and shows the same threads on your desktop, the web and your phone. That machine has to stay on. `zode t3` makes a sandbox that machine.

```bash
zode login
zode t3 --repo owner/repo
```


Open the link on your phone, check the code matches and approve. The sandbox now shows up as a machine in T3 Code on your phone, your desktop and [app.t3.codes](https://app.t3.codes).

## From the console or an agent

- **Console:** open the sandbox, then **Integrations** > **T3 Code**. Add a repository if you want one, press **Set up T3 Code**, and approve the code it shows.
- **Agents:** with [Zode's MCP server](/cli/mcp), ask your agent to set up T3 Code on a sandbox. It uses the `t3_setup` and `t3_status` tools and hands you the code to approve.
- **API:** `POST /v1/sandboxes/{id}/t3` with an optional `{"repo": "owner/repo"}` starts setup; `GET /v1/sandboxes/{id}/t3` returns the state (`starting`, `awaiting_approval` with `user_code` and `verification_url`, `connected`, `expired`, `failed`, `stopped`).

## What it does

1. Makes a sandbox named `t3`, or wakes it if you already have one by that name.
2. Installs T3 Code with T3's own installer.
3. Clones `--repo` into `~/work` (a partial clone, so big repositories arrive fast). Private GitHub repositories work once your workspace has GitHub linked (`zode github`).
4. Installs T3 Code's background service and keeps it running across a stop and start.
5. Runs `t3 up --connect --headless`, which prints the sign-in code.
6. Adds the clone as a T3 project, so the apps can open it on this machine.

Zode never sees your T3 account. You approve the code yourself.

```bash
zode t3 [name] [--repo owner/repo | URL] [--size small|medium|large|xlarge]
zode t3 status [name]      # how far setup got, the code to approve, the projects
```

Run it again on the same sandbox to add another repository or to see the status. Nothing that is already there is installed twice, and a machine that is already signed in is not asked again.

## Sign the agents in

T3 Code starts Claude Code and Codex inside the sandbox, so they sign in there, once:

```bash
zode ssh t3 -- claude                      # or
zode ssh t3 -- codex login --device-auth
```

Or sign in from T3 Code's provider settings.

## Stopping

`zode stop t3` pauses the sandbox with its memory kept, and billing stops. T3 Code cannot reach a stopped machine, so start it again before you open T3: `zode start t3`, or from your phone open the sandbox's page in the console (`zode t3` prints the link) and press **Start**. Waking it from T3 Code itself is planned.
